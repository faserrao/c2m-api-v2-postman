# New Developer Quick Start

Welcome to the C2M API V2 project! This guide will get you making your first API change in **5 minutes**.

## Overview

The C2M API V2 uses a unique data-driven approach:

```
EBNF Data Dictionary → OpenAPI Spec → Postman Collections → Docs → SDKs
```

You only edit the **EBNF file**. Everything else is auto-generated by the pipeline.

## Your First Change (5 Minutes)

### Step 1: Clone and Setup (One Time)

```bash
# Clone the repository
git clone https://github.com/click2mail/c2m-api-v2-postman.git
cd c2m-api-v2-postman

# Install dependencies
make install

# This takes ~5 minutes (one-time setup)
```

### Step 2: Edit the EBNF File

The **EBNF data dictionary** is the single source of truth for the entire API:

```bash
# Open in your editor
code data_dictionary/c2mapiv2-dd.ebnf
```

Let's add a simple optional field to an endpoint. Find `submitSingleDocParams` (around line 616):

```ebnf
submitSingleDocParams =
      [ jobTemplate ]
    + docSourceAll
    + recipientAddressSource
    + [ paymentDetails ]
    + [ returnAddress ]
    + [ jobOptions ]
    + [ tags ] ;
```

Add a new optional field (in square brackets = optional):

```ebnf
submitSingleDocParams =
      [ jobTemplate ]
    + docSourceAll
    + recipientAddressSource
    + [ paymentDetails ]
    + [ returnAddress ]
    + [ priority ]           (* NEW FIELD - priority level *)
    + [ jobOptions ]
    + [ tags ] ;
```

Now define the field type (add after line 650):

```ebnf
priority = "standard" | "rush" | "overnight" ;
```

### Step 3: Validate Your Changes

```bash
# Run validation (catches 80% of errors before committing)
./scripts/validate-before-commit.sh
```

You should see:
```
✓ EBNF syntax valid
✓ No duplicate definitions
✓ Safe to commit!
```

### Step 4: Preview What Will Change

```bash
# See what will change in the OpenAPI spec
./scripts/preview-ebnf-changes.sh
```

This shows you exactly what will be generated from your EBNF changes.

### Step 5: Push Your Changes

```bash
# Option A: All-in-one safe push (recommended for new developers)
./scripts/safe-push.sh "Add priority field to submitSingleDocParams"

# Option B: Manual steps (if you want more control)
git add data_dictionary/
git commit -m "Add priority field to submitSingleDocParams"
git push origin main
```

### Step 6: Monitor the Workflow

GitHub Actions will automatically:
1. Generate OpenAPI spec (30 seconds)
2. Generate Postman collections (60 seconds)
3. Publish to Postman workspace (30 seconds)
4. Deploy documentation (60 seconds)
5. Generate SDKs for 11 languages (30 seconds)

Monitor progress:
https://github.com/click2mail/c2m-api-v2-postman/actions

**Expected time**: 3-4 minutes total

## Common Issues

**"0 productions parsed"**
- You have a syntax error in EBNF
- Run `./scripts/validate-before-commit.sh` to see details
- Common cause: Dictionary syntax `{ string : string }` (not supported)

**"Duplicate definition"**
- You defined something twice
- Validation script will show which identifier

**"Workflow failed"**
- Check GitHub Actions logs
- Common fix: `git revert HEAD && git push` (rollback)

## Key Concepts

**EBNF = Single Source of Truth**
- All API structure defined here
- OpenAPI spec generated from EBNF
- Postman collections generated from OpenAPI
- Documentation generated from OpenAPI
- SDKs generated from OpenAPI

**Optional vs Required**
- Square brackets `[ field ]` = optional
- No brackets = required

**Arrays**
- Curly braces `{ element }` = array of elements

**Enums**
- Pipe symbol `"value1" | "value2"` = one of these values

**Comments**
- `(* This is a comment *)`

## Pro Tips

1. **Always validate first** - Run `./scripts/validate-before-commit.sh`
2. **Preview before pushing** - Run `./scripts/preview-ebnf-changes.sh`
3. **Use safe-push.sh** - Until you're comfortable with the workflow
4. **Small changes** - Easier to review and debug
5. **Test locally** - Run local build before pushing (optional but recommended)
